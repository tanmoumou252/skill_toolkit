# Skill: Lean-Readme (极简分级 README 生成器)

## 1. 核心定位与原则
- **路标原则**：README 是方向指引（Orientation Map），不是技术白皮书。仅保留：定位、入口、消费方式与暗坑。
- **减法原则**：凡是看文件名就能懂的信息一律不写；严禁打印全量目录树；严禁逐一罗列文件。
- **零修饰原则**：全文严禁出现任何 Emoji；严禁使用“强大、优雅、开箱即用”等主观营销词汇。

---

## 2. 仓库形态判定与“无命令”处置规则

在输出前，必须先静态分析仓库或当前目录的代码特征，按以下三类规则执行：

### 规则 A：可运行工程（应用 / CLI / 服务）
- **判定标准**：存在**实际可执行的启动入口**——`package.json` 含 `start`/`dev`/`bin` 等启动脚本（仅含 `test`/`lint` 等验证脚本不算，此类按实际消费方式归入规则 B/C）、或 `Makefile` 含运行目标、`Dockerfile` 含 `CMD`/`ENTRYPOINT`、`main.go` 等。
- **标题与格式**：保留 `## 快速起步`，提供 **3~5 行以内**真实的安装与启动命令；严禁为凑格式生成仓库中不存在的启动命令。

### 规则 B：被动消费工程（配置 / 插件 / 规则 / Dotfiles / 模板）—— **无运行命令**
- **判定标准**：无需本地独立运行，作为外部软件的输入或宿主依赖。
- **标题降级**：**严禁使用** `## 快速起步` 或 ```bash``` 命令块。
- **替代标题**：改为 `## 生效方式` 或 `## 放置路径`。
- **内容规范**：用 1~2 句话纯文字说明 **“被谁读取、应放置在哪个目标目录”**（例如：“供 Cursor/Claude 作为 Agent 规则加载，需放置于项目根目录 `skills/` 下”）。

### 规则 C：纯静态工程（SQL脚本 / 数据集 / Schema契约 / 静态资产 / 规范文档）—— **无运行命令**
- **判定标准**：仅供查阅、静态引用或作为数据库迁移产物，无宿主放置需求。
- **强制剪枝**：**直接彻底删除“起步/接入”整个小节**！正文从项目一句话定位**直接衔接** `## 核心入口` 或 `## 目录导航`，严禁强加任何使用方法标题。

---

## 3. 强负向约束 (Strict Negative Constraints)

1. **绝对禁止虚假命令**：无编译/运行入口的仓库，**绝对禁止输出 ```bash``` 代码块**，严禁捏造 `npm start`、`python main.py` 等虚构指令。
2. **绝对禁止占位符**：严禁输出 `[在此填写]`、`TODO` 等未填充模板。若信息缺失，直接删节。
3. **严禁全量清单**：只准指出 **1~2 个最核心的首读入口**，严禁对目录下所有文件逐行打标签。
4. **代码与配置长度红线**：接口示例或调用片段**不得超过 8 行**。
5. **篇幅硬指标**：根目录 35~55 行内，子目录 20~35 行内，严禁扩写成长篇文档。
6. **保留义务（反过度精简红线）**：以下信息不得为凑篇幅而删除——
   - **既有截图/图片/示意图引用**及其说明文字（含「只做演示、不保证某行为」类限定语；承载真实差异信息的演示图不是流水账）；
   - **客观踩坑与暗坑**：别名遮蔽、时序依赖、平台已知缺陷行为、需人工介入的开关；
   - **部署关键约束**：安装/复制目标路径、必填配置项、版本基线、生效前提、需关闭的宿主开关；
   - **唯一信息源**：该信息若仅此一处记载，删前必须先确认他处已有等价副本，否则先迁移到正确位置再删，禁止直接丢弃。
7. **资产引用同生共死**：图片/文件引用与被引用资产同进同退——删除引用时必须同步处置资产文件（一并删除，或显式说明保留理由），保留资产文件时必须保留可命中其路径的引用；只删引用留下无主资产、或只留资产删引用，均属缺陷。
8. **红线冲突裁决**：保留义务与篇幅红线冲突时，先收敛措辞、合并行；仍超限则允许小幅超线并显式注明原因，严禁静默删除受保护信息。

## 4. 分级交付规格

### A. 根目录规格 (Workspace Root)
- **项目定义**：单句陈述本质（是什么、产出什么、给谁用）。
- **起步 / 生效方式**：
  - 有运行命令：`## 快速起步`（<=5行真实命令）
  - 配置/规则类：`## 生效方式`（纯文本说明放置路径与加载方）
  - 纯数据/资产：**整节彻底删除，不输出任何标题**
- **架构导航**：仅列出一级核心子目录，单行说明核心职责。
- **核心入口**：主启动文件、主配置、总规则或主 Schema 的相对路径。
- **全局约束**：环境版本基线或全局修改红线（若无硬约束则省略）。

### B. 子目录规格 (Sub-directory)
- **职责边界**：
  - `负责`：本目录处理的核心单一职责。
  - `不负责`：交由其他模块承接的逻辑（若边界清晰则省略）。
- **核心入口**：阅读本目录时首选看的 1~2 个文件及其作用。
- **消费/调用约定**：外部调用的最简接口片段（<=8行）；若无代码接口，用一句话说明该目录资源被谁读取。
- **注意事项与暗坑**：时序依赖、配置冲突或易错点（若无客观陷阱则省略）。

## 5. 目标输出示例（供模型直接参照）

### [场景 1：有命令工程（如服务端应用）]
````markdown
# Auth Service

负责全系统的用户鉴权、Token 签发与权限校验服务。

## 快速起步

```bash
pnpm install
pnpm dev
```

## 架构导航

- src/routes: API 路由入口
- src/services: 鉴权业务核心逻辑
- src/config: 密钥与环境变量映射

## 核心入口

- 服务入口: src/index.ts
- 配置文件: config/default.yaml

## 全局约束

- Node.js >= 20.0.0，且依赖外部 Redis 实例正常运行。
````

### [场景 2：无命令工程 A（配置/规则类）]
```markdown
# Nginx Configurations

全站生产与预发环境的反向代理与负载均衡配置。

## 生效方式

由运维发布流水线拉取，软链接至宿主机的 `/etc/nginx/conf.d/` 目录，通过 `nginx -s reload` 热重载生效。

## 架构导航

- prod: 生产集群配置集
- staging: 预发测试集群配置集
- snippets: 通用 SSL 与安全策略片段

## 核心入口

- 生产主入口: prod/main.conf
- SSL 通用规则: snippets/ssl-params.conf

## 修改约束

- 修改任何 `.conf` 文件必须保证语法通过校验，严禁在生产配置中开启调试日志。
```

### [场景 3：无命令工程 B（纯数据 / Schema / 资产类 —— 彻底剪枝）]
```markdown
# Database Schemas

管理业务核心数据库的表结构定义与版本基线。

## 目录索引

- tables: 业务全量 DDL 表结构
- functions: 共享存储过程与触发器
- seeds: 本地测试基准字典数据

## 核心入口

- 主库核心基线: tables/core_schema.sql
- 权限与用户表: tables/auth_users.sql

## 约束说明

- 所有新增字段必须包含 COMMENT 注释，历史表结构变更必须保持向下兼容。
```
