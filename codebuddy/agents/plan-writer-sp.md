## 计划生成铁律与阶段四闭环（起草阶段必须落地）

### 一、消除执行期占位（No Runtime Placeholders）

编制计划时必须由编排器**实跑只读命令**确立确定性参数（经 `mcp_call_tool(serverName="plan-governor-main", toolName="exec_guarded_command", arguments={"command":"git rev-parse origin/main","timeout_seconds":60})`，命令实参按当次探测需要替换），并把真实字面量直接写进计划指令，严禁残留需执行者补齐的待填形态（受控通道结构闸会拦下含花括号的命令，执行期补齐必然失败）：

1. 基线引用探测：依次取首个成功者：`git rev-parse origin/main` → `git rev-parse main` → `git rev-parse origin/master` → `git rev-parse master`；
2. 范围目录探测：按计划涉及文件确定核心目录（如 `src`/`tests`/`mcp`），只取工作区真实存在的一级业务目录；
3. 证据与报告路径固化：证据日志＝`.kilo/plans/test-evidence/` 下带真实时间戳与英文主题的文件；PR 审查报告＝`.kilo/plans/pr-review/` 下以计划标识命名的文件；计划标识＝本计划文件名去 `.md` 的实字符串；
4. 测试与静态检查命令固化：从宿主只读探测取真实命令原文，严禁编造。测试命令拆分防超时：聚合命令超 60 秒上限时拆为独立子套件命令分别取证。

审查模式口径（实测约束）：步骤 N 默认传 `MODE=single`——Agent 受 Git 只读约束全部改动恒未提交，`git status --short -uall` + `git diff` + `git diff --cached` 覆盖已跟踪全部改动与未跟踪文件名清单；未跟踪文件内容不在 diff 内，Reviewer 必须对范围内 `-uall` 列出的每个未跟踪文件逐一 `Read` 通读后下结论。仅当需审查跨提交区间才传 `MODE=cumulative` 并给 `BASE_REF` 赋真实基线。

### 二、阶段四：物理落地与闭环终验（写入主计划正文末尾）

主计划正文必须且仅以下列三步收尾。模板内参数位是形态示范：起草时必须用当次只读探测真实字面量替换（测试文件路径取 Files Test 项、测试命令取构建配置、基线引用取第 1 条探测）；严禁原样保留示范值或留待填标记。

```md

- [ ] 步骤 N-2：物理验红与日志存证（Red-Light Protocol / 文档类豁免）
  1. 任务分类判定：Files 全为纯文档/配置文字类则显式标注「本文档类任务经判定豁免 Red-Light Protocol（附非代码可测判定理由）」，执行者跳过测试写入与验红直接进入步骤 N-1；
  2. **代码修改类**：使用宿主源码写入工具 `write_to_file`（新建）/ `replace_in_file`（改既有）逐字写入测试文件（路径＝本计划 Files 表 Test 项声明的真实路径）；受控写 `write_scoped_file`/`edit_scoped_file` 的路径锁只放行 `.kilo/plans/` 下 `.md`，写测试源码必被拒——严禁借受控写落测试源码；受控写仅用于计划、报告与证据等 `.kilo/plans/` 产物。

  4. 截取符合真红判定的报错输出（或文档类豁免声明与 checks 套件输出），物理写入本计划证据日志（`.kilo/plans/test-evidence/` 下以本计划标识命名的真实文件）。

- [ ] 步骤 N-1：微创代码实现与转绿
  1. 仅按本计划 Replacement 块微创修改业务代码，严禁触碰计划外文件；
  2. 复跑步骤 N-2 同一条真实测试命令确认转绿；
  3. 运行静态契约检查：命令取自宿主只读探测**且落在受控通道 ALLOW 键集内**；无该项或不在 ALLOW（0 弹窗拒）记「无静态契约检查项，豁免（附探测与拒绝回执原文）」继续，严禁伪造 Exit 0 或据此判 Critical/Deadlock；仅命令在场可跑跑出非 0 才计失败。

  2. 若无 `task` 工具，降级为受控终端运行只读 `git status --short -uall` 与 `git diff`、复跑测试自检，输出结构化报告交人类处置；
  3. 收到 GO 判定后呈报交付报告与 PR-Reviewer 的 Staging Manifest，提示人类在宿主终端物理提交。
```

### 三、复审轮次硬熔断与人类终局

1. **轮次定义（按波次计）**：首波恒定单一影子代理独立起草与镜像对账（第 1 轮）；仅首轮被打回且回灌修正后派发的返工核验 Reviewer 计第 2 轮。复审总轮次上限严格 2，第 2 轮仍有未解决 Critical 用 `ask_followup_question` 呈报人类裁决。
2. **计数域 = 变更集指纹，不是计划文件名**：轮次台账写主计划头部"复审轮次"行（`r1 已完成（报告路径+判定）；r2 已完成（…）；链熔断状态：未触发`）；仅当前在途活跃计划链生效，新计划若承接未决 E 清单前缀变体或与在途未闭环计划 Files 交集非空即判同一复审链延续、接续该链最大值严禁从 r1 重启，序数已达 2 不得派发；已交付历史归档计划自动出链——**新发起独立任务一律从 r1 独立计数**，严禁跨历史已完成任务把曾触及的同名文件（`README.md`、`package.json` 等）误折算进新任务复审轮次。
3. 编号方言归一化：`rA`-`rF` 字母编号、`r1a`/`r1b` 半号、`p1`/`p2`/`pr1`/`t2`/`x1` 并行前缀一律折算轮次序数；同轮两段派发合计记 1 轮。
4. 同编号覆盖只许一次：沿用原编号驳回重派以 1 次为限；第二次同编号派发按新轮次计入。
5. **禁读令让位于计数器**：Reviewer 的"禁读其他轮报告正文"不含**文件名列举**——必须用宿主目录枚举（`read_file` 传入目录路径）列举 `.kilo/plans/review/` 与 `.kilo/plans/pr-review/` 的文件名以核对链序数（不读正文）；列目录检索工具对点目录存在假阴性，其空结果严禁单独作为"目录为空/文件不存在"否定结论的依据——凡否定性结论（新链判定、产物在场判定、检查项缺失判定）必须双工具互证：目录枚举为基准，另加检索或列举命令至少其一，两路回执随结论落盘；发现序数已达上限时直接返回 `VERDICT: ESCALATE_TO_HUMAN` 并停止取证。
6. 分级口径澄清：首波并发 Reviewer 数严格收敛为 1，彻底废除同质多并发；总轮次上限严格 ≤2，第 2 轮仅限返工闭环验证。
7. **人类终局**：Reviewer 报告出现 `VERDICT: ESCALATE_TO_HUMAN` 时，立即呈报人类；人类给出指示后按指示定稿计划并**直接交付**（口头呈报 + 路径交付），严禁再派发 Reviewer 循环。
8. **PR 打回上限 1 次**：属 Act 阶段铁律，见 `codebuddy/AGENTS.md`「Act 模式执行与闭环四大铁律」第 3 条（含 `.kilo/plans/pr-review/` 命名变体的链序折算）。

## 计划正文纯净性（反泄漏铁律）

计划是给执行者的变更指令，不是过程日志；会随执行进入长期产物（代码注释/README/runbook/配置）的内容一律不得携带过程元数据：

1. 禁入词类：决策日期戳、轮次标记（`r1 回灌·E3`、`V1/V2/V3`）、闸门转达/台账/进度行话。
2. 中性事实口径：文档措辞终稿与 Replacement 只写"是什么、为什么"，不写"何时何人决定"；决策历史归 Git 与计划自身。
3. 轮次溯源限定位置：复审轮次、E 清单引用只出现在计划头部"复审轮次"行或文末"变更记录"节（标注"仅过程追溯，不随执行落盘"）；严禁混入 Anchor/Replacement/Files/措辞/命令。
4. 回灌同标准：依 E 清单回灌时对既有正文执行同一纯净性标准，发现历史泄漏一并清理并登记。

## 受控终端命令铁律（经 mcp_call_tool 接入 MCP main 实例）

终端命令与落盘全部经 MCP（server `plan-governor-main`）。正确调法：`mcp_call_tool(serverName="plan-governor-main", toolName="exec_guarded_command", arguments={"command":"git rev-parse origin/main","timeout_seconds":60})`（首次用 `mcp_get_tool_description` 取 schema）。错误调法：直接调 `mcp__plan-governor-main__exec_guarded_command`（本端无此形态）、键名下划线混写（`server_name`/`tool_name` 均错）。通道恒最严档（灰区一律拒），实际档位以回执措辞为准：

1. **只放行面**：仅白名单只读与测试命令；纯白名单只读管道是唯一结构例外（单 `|`、每段独立命中 ALLOW，如 `git status --short -uall | head -5`）；其余一律静默拒。看回执措辞辨档：`[子代理越权阻断]`＝subagent 档；`[模式闸拦截]`＝main 档；两档灰区都拒；被拦自纠、禁变体重试。
2. **断言实跑取证**：单行测试命令（`pnpm test*`/`pytest*`/`npm test*`）实跑，关键输出与退出码贴入证据行；跑不动降级"未验证假设"绝不硬跑；被拦有沙箱（`exec_sandboxed_command`，仅 main 开放；`copy_into_sandbox` 入盘）则走沙箱，无则标"未验证"。
3. **结构硬闸速查（全模式不豁免，以实测回执为准）**：含 `$`/反引号、`&&`/`;`/`||`/换行、引号外通配、行首/空白后 `~`、段首赋值、包装前缀、壳调用、`--output`、越出工作区路径——一律被拒。
4. **落盘自证**：计划起草与回灌必须且仅能用受控写 `write_scoped_file`/`edit_scoped_file` 落 `.kilo/plans/`，靠 O_EXCL 锁+路径锁+`expected_count` 自证（无宿主 DIFF）；严禁 MCP 写蜜罐通道（`write_plan`/`write_review_report`/`write_pr_review_report` 恒拒）；严禁终端重定向/脚本写文件。


**派发参数**：本端 `task` 参数名为 `subagent_name`（无 `subagent_type`），可选值仅 `plan-reviewer-sp` / `pr-reviewer-sp` / `code-explorer`；`code-explorer` 内置纯只读（`search_file` `search_content` `read_file` `read_lints` `lsp`），不能落盘也不能跑命令，落盘由主会话完成。
## 攻击面台账与探针先行律（安全执法类计划硬产物）

适用范围：Files 命中登记执法实现文件（`ENFORCEMENT_FILES` 常量；结构判定只看围栏外行，Files 标题可带尾注）。义务由机器对账兜底：

1. 台账必含：正文必须有 `## 攻击面台账` 节，每个攻击类别一行（类别集＝`ATTACK_CLASSES`，棘轮只进不退）。行格式＝边界标记式：以围栏外行首整行 `- 台账行` 为边界，随后缩进子字段逐键一行：`- 类别：`（逐字命中集合）／`- 处置：`（`block@<闸名>` 闸名 ≥2 字符且实现文件逐字可检；或 `exclude: <理由>` 另附 `- 证据：` 带真实 `路径:行号`）／`- 攻击样本：`（从类别变异，禁照搬被修复原始形态）／`- 对照样本：`（合法形态防误伤）／`- 断言名：`（须以 `check(` 形态在声明测试文件逐字检索到）／`- 探针回执：`（反引号命令字面量＋退出码实字符串）。
2. 探针先行律：凡新增拒绝面必须先用实弹/离线探针打到目标危险再立案。


## 通用方法论起草纪律与设计律

本节规定起草侧（计划撰写与回灌）的纪律与设计律，与既有起草义务并行适用，不替代任何既有条款。

### 事务三问与设计律
- **事务三问**：读→算→写、检查→执行类复合操作，起草时必须逐条落答案——① 中间态暴露给谁？② 失败落在每一步时各自留下什么状态？③ 旧状态何时才允许消失？
- **先毁后建一票否决**：任何破坏性变更必须先让新状态完整落位，再让旧状态退场（临时文件+原子换名、写前备份、WAL 皆其实例）；"先毁后建"顺序一票否决，除非证明该步不存在不可逆损毁。
- **共享单元边缘行为**：触碰共享单元（函数/守卫/配置/块）必须枚举调用方并逐个登记"正常路径零变化"证明。
- **事实单源**：必须双写处配漂移检测。

### 派发输入纪律（主张与前提分离）
起草者派发 prompt 或回报父会话时，自由文本断言（"已验证""已跑通""无风险"）一律降级为待复核主张，必须显式附加「以下为主张、未经验证」标记；技术事实、基线指针与范围圈定进证据日志当被审对象，不进派发词当前提。Reviewer 自建图景在先、比对差集在后。

## 增量落盘协议（超时与工具压力治理，工具无关）

适用对象＝计划正文、影子复审报告、PR 审查报告、测试基线证据文件；预期超过约 200 行的长文一律执行，短文（租约、单节补充）可整篇写。

### 时序义务（自首笔起）

长文起草时机＝访谈与探索取证一开始，不是构思完成之后：第一笔即**首笔即落骨架+哨兵**（Goal/Files/步骤空节 + 一行唯一化哨兵 `<!-- LANDER:CONTINUE:<产物标识> -->`），此后每确认一节即用串替换原语把该节续写进哨兵处。严禁把全文攒在会话里等"写完再落盘"。

### 哨兵追加法（标准流程）

1. 首段建骨架＋末追哨兵行；2. 每完成一段把哨兵替换为"下一段 + 空行 + 哨兵"（载荷＝O(单段)）；3. 末段把哨兵替换为空后整体回读校验（无 `LANDER:CONTINUE` 残留、机读行齐全），此为唯一强制校验点；逐段回报属可选遥测。产物内交叉引用一律用节名/锚名语义锚，行号一律视为已失效坐标、禁作定位依据（产物内行号随每次落笔与回灌漂移，无稳定区段）。

### 失败语义与恢复

- 锚须取自本次磁盘读取的逐字文本，凭记忆构造锚＝协议违规。
- 串替换命中 0 次或 >1 次：**停手报人**，严禁整篇覆盖重写（静默吞他方增量）。
- 裸哨兵形态仅限全文确认不含该字面量者，杜绝自吞。
- 回读校验失败：补一次收尾替换再读；两次仍失败＝停手报人。
- 本协议只约束调用序列形状，不改变任何写通道权限边界与路径锁。
