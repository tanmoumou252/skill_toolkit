## 自足审查规程

⑥ **幻觉断言举证责任**：判「虚构 API/幻觉路径/幻觉依赖」须负举证责任——以 `read`/`grep` 证明全局不存在该符号/工具/配置；严禁把计划草稿自身遗漏倒打一耙为被审改动「幻觉」。

### 一、双轨审查模式

1. MODE=single（默认）：先 `git status --short -uall` 定位全部改动，再 `git diff`（未暂存）与 `git diff --cached`（已暂存）取 hunks。
2. MODE=cumulative：先 `git status --short -uall`，再 `git diff BASE_REF` 与 `git diff BASE_REF -- SCOPE_DIRS`（基线/范围以调度者真实字面量代入）。
3. **未跟踪新文件铁律**：`git diff` 不显示未跟踪文件；凡 `git status --short -uall` 列出的未跟踪新增文件（尤其新增测试）严禁依赖 diff 断言，必须 `read` 全文通读核查用例有效性。


### 二、证据日志真红核验

读 `EVIDENCE_LOG` 逐条判定，先核对 `PLAN_PATH` 是否显式标注「本文档类任务经判定豁免 Red-Light Protocol」：
- 已声明豁免：确认常驻不变式 Exit 0 且改动纯文本即判通过，严禁因"无代码真红日志"判 Critical；
- 代码修改类：确认含断言/比对失败、目标契约缺失型类型错误、业务领域异常或异步时序超时之一，排除 SyntaxError/Cannot find module/脚手架崩溃等假红；日志缺失/为空/只含假红 → **Critical**。

### 三、动态复测与静态契约

- 复跑受影响单测须全 Exit 0，单条上限 60 秒，超时或被拦时逐条标"复跑受限，未经独立复跑验证"，严禁以基线替代或仅凭基线判 GO；
- 静态契约检查命令须取自宿主只读探测**且落在 ALLOW 键集内**；无该项或不在 ALLOW（0 弹窗拒）则记「无静态契约检查项，豁免（附探测与拒绝回执）」继续，严禁伪造 Exit 0 或据此判 Critical；仅命令在场可跑跑出非 0 才计失败。**本豁免不适用于四问**。

### 四、工具轮次保护矩阵（防 Turn 耗尽）

diff 涉及文件 >5 时分层走查：核心层（状态转移/全局变量/核心接口）全量 `read` 追溯调用链，边缘层（文案/纯类型/独立配置）结合 diff 与 `grep` 定点验证，严禁通读无关大文件。

正交检查轴，与其余审查义务并行；同一对象被多处约束时按更严者执行。各轴细则归档于 `spec/anchor-library/`，本处不复述。

- 一、文档取证义务：变更路径上的每个 IO/事务/并发/序列化调用，其**失败语义必须对权威文档取证**，禁止凭记忆判定。
- 二、遗漏型审查：核验之外强制**遗漏型审查**——枚举失败空间与输入空间，逐项问"有没有任何测试"，空白区本身即发现，写入报告独立小节。
- 三、两遍法与披露解耦：第一遍屏蔽作者叙事只看代码盘面，第二遍才读声明比对是否被话术带偏——**两遍法与披露解耦**；作者披露只能降低责难、不能降低等级。**严重度按四要素裁定**（可达条件/实际影响范围/可逆性与恢复方式/有证据支持的触发概率），概率与披露不参与降级。
- 四、事务三问：读→算→写、检查→执行类复合操作强制**事务三问**——① 中间态暴露给谁？② 每步失败各留下什么状态？③ 旧状态何时才允许消失？
- 五、影响面：耦合谱系与探测五法——**影响面按耦合谱系探**（L1 语法/L2 词汇/L3 契约/L4 枚举义务/L5 演化），不按引用找；探测五法（可观测面反演/枚举面盘点/承诺提取/差分探测/消费者人格扫荡）。
- 六、异源透镜：一份审查至少含一个**异源透镜**视角（外部文档/数据完整性/操作者/静态分析器），透镜在 Reviewer 内部轮换，严禁增派 Reviewer 或突破首波并发=1。
- 七、设计律：**先毁后建**一票否决——破坏性变更前新状态先完整落位再退场旧状态；触碰共享单元须枚举调用方并逐个登记"正常路径零变化"证明；事实单源，必须双写处配漂移检测。
- 八、严重度公理：见三——**严重度按四要素裁定**，禁止按缺陷类别自动判级。
- 九、派发输入纪律：审查者先自地面真相自建图景再读派发输入；报告必含"**与派发主张的差集**"一节，差集才是产出。
- 十、**一页速查**（审查八问，清单跑完逐条过）：①失败语义权威文档怎么说？②哪些失败/输入空间无测试？③严重度被披露降级了吗？④事务三问（中间态/逐失败残留/旧态退场时序）答了吗？⑤图景自建还是派发输入给的，差集写了吗？⑥用了哪个异源透镜？⑦改变了一切离开系统的字符串/格式/计数吗，全库检索/枚举盘点/承诺图做了吗？⑧四要素逐项盘了吗，概率有证据、披露没参与降级吧？

*本次审批仅为代码变更审查——审查通过不等于合入授权；合入、提交或推送需用户在审查通过后另行明确授权。*

## 增量落盘协议（超时与工具压力治理，工具无关）

适用对象＝计划正文、影子复审报告、PR 审查报告、测试基线证据文件；预期超过约 200 行的长文一律执行，短文（租约、单节补充）可整篇写。

### 时序义务（自首笔起）

长文起草时机＝访谈与探索取证一开始，不是构思完成之后：第一笔即**首笔即落骨架+哨兵**（Goal/Files/步骤空节 + 一行唯一化哨兵 `<!-- LANDER:CONTINUE:<产物标识> -->`），此后每确认一节即用串替换原语把该节续写进哨兵处。严禁把全文攒在会话里等"写完再落盘"。

### 哨兵追加法（标准流程）

1. 首段建骨架＋末追哨兵行；2. 每完成一段把哨兵替换为"下一段 + 空行 + 哨兵"（载荷＝O(单段)）；3. 末段把哨兵替换为空后整体回读校验（无 `LANDER:CONTINUE` 残留、机读行齐全），此为唯一强制校验点；逐段回报属可选遥测。产物内交叉引用一律用节名/锚名语义锚，行号一律视为已失效坐标、禁作定位依据（产物内行号随每次落笔与回灌漂移，无稳定区段）。

### 失败语义与恢复

- 锚须取自本次磁盘读取的逐字文本，凭记忆构造锚＝协议违规。
- 串替换命中 0 次或 >1 次：**停手报人**，严禁整篇覆盖重写（静默吞他方增量）。
- 裸哨兵形态仅限全文确认不含该字面量者，杜绝自吞。
- 回读校验失败：补一次收尾替换再读；两次仍失败＝停手报人。
- 本协议只约束调用序列形状，不改变任何写通道权限边界与路径锁。
