{{g80}}## 计划正文纯净性（反泄漏铁律）
{{g81}}
{{g82}}计划是给执行者的变更指令，不是过程日志；会随执行进入长期产物（代码注释/README/runbook/配置）的内容一律不得携带过程元数据：
{{g83}}
{{g84}}1. 禁入词类：决策日期戳、轮次标记（`r1 回灌·E3`、`V1/V2/V3`）、闸门转达/台账/进度行话。
{{g85}}2. 中性事实口径：文档措辞终稿与 Replacement 只写"是什么、为什么"，不写"何时何人决定"；决策历史归 Git 与计划自身。
{{g86}}3. 轮次溯源限定位置：复审轮次、E 清单引用只出现在计划头部"复审轮次"行或文末"变更记录"节（标注"仅过程追溯，不随执行落盘"）；严禁混入 Anchor/Replacement/Files/措辞/命令。
{{g87}}4. 回灌同标准：依 E 清单回灌时对既有正文执行同一纯净性标准，发现历史泄漏一并清理并登记。

{{g93}}## 攻击面台账与探针先行律（安全执法类计划硬产物）
{{g94}}
{{g95}}适用范围：Files 命中登记执法实现文件（登记清单由派发 prompt 声明的当前仓库检查套件执行；结构判定只看围栏外行，Files 标题可带尾注）。义务由机器对账兜底：
{{g96}}
{{g97}}1. 台账必含：正文必须有 `## 攻击面台账` 节，每个攻击类别一行（类别集由派发 prompt 声明的当前仓库检查套件执行，棘轮只进不退）。行格式＝边界标记式：以围栏外行首整行 `- 台账行` 为边界，随后缩进子字段逐键一行：`- 类别：`（逐字命中集合）／`- 处置：`（`block@<闸名>` 闸名 ≥2 字符且实现文件逐字可检；或 `exclude: <理由>` 另附 `- 证据：` 带真实 `路径:行号`）／`- 攻击样本：`（从类别变异，禁照搬被修复原始形态）／`- 对照样本：`（合法形态防误伤）／`- 断言名：`（须以 `check(` 形态在声明测试文件逐字检索到）／`- 探针回执：`（反引号命令字面量＋退出码实字符串）。
{{g98}}2. 探针先行律：凡新增拒绝面必须先用实弹/离线探针打到目标危险再立案。
