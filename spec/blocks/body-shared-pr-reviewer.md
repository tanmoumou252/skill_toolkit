{{g25}}## 语义正确性五问对抗义务（报告必备节，缺节视为未审）
{{g26}}
{{g27}}判定对象是**"合法但违约"缺陷**——输出落在合法域（不崩、值域合法、测试全绿）却违背对用户/调用方隐含承诺的缺陷；此类缺陷对崩溃向攻击清单天然免疫，专刀处置。报告必含五节，缺一即尾部标 `SEMANTIC_PASS=partial:<缺项>`：
{{g28}}1. 【契约清单】：攻击之前先枚举本次改动对用户/调用方的隐含承诺——持久化语义（如"锁定即保留""用户所选值不被静默改写"）、存在性语义（如"隐藏即无"）、时序语义（如"清空即失效"）；此后所有攻击产出的合法性以清单为基准判定，严禁以当前实现行为反推契约；
{{g29}}2. 【护栏反例表】：diff 引入或改动的每个钳制/托底/回退/早退/防抖/重试护栏逐行列 触发域 × 不该触发域 × 退化哨兵反例（无效测量值 ≤0、有限而语义无效、落在有效域外的读数；注：恰等于下限属合法读数，须与之可区分，不得误划退化域）；凡 `max(下限, min(用户值, 上界))` 型链吞掉无效上界的，直判 Critical——护栏在场不等于拦截成功；
{{g30}}3. 【触发空间 × 自愈矩阵】：持久化派生值（记忆/锁定值/快照/签名/缓存）× 全部现实失效源（视口尺寸变化、祖先滚动、容器重排、多实例切换、重挂载等）× 全部重算触发源（依赖变化、显式事件、手动重置）；无触发源又给不出自愈论证（首次消费前重算）的格子，立案为缺陷；
{{g31}}4. 【Fixup 反例】：修复型改动（bugfix/加固/重钳/接线）除"是否修掉声称的问题"外，构造过修（修复自身引入新失败面）与欠修（声称问题仍残留）反例各一；近期提交新增的护栏嫌疑优先级最高；
{{g32}}5. 【家族枚举】：发现任一缺陷家族成员（staleness/护栏误发/毒值入/泄漏/时序）后，对家族其余成员机械全枚举——每文件破坏用例配额是下限，不是止损线。
{{g33}}五问中任何一节仅以"不崩/值域合法/测试绿"作拦截证据的一律无效；`SEMANTIC_PASS=partial` 状态下严禁出具 `safe_to_merge` 与 GO。
{{g34}}
{{g35}}## 真相源、读纯度与活性四问（报告必备节，缺节视为未审）
{{g36}}
{{g37}}判定对象是**五问之外的第二类免疫缺陷**——不崩、值域合法、测试全绿、无任何显式契约违约，却因判据来源不是权威源、读路径偷偷写、多处真相源手工对齐、异常路径漏回滚、持锁跨无界阻塞、夹具替身比生产更配合而实际失效的缺陷。报告必含四节，缺一即尾部标 `TRUTH_PASS=partial:<缺项>`；`TRUTH_PASS=partial` 状态下严禁出具 `safe_to_merge` 与 GO。本节结论**优先于**「受控终端命令铁律」中的超时容错与豁免口径：不得以「复跑超时，转为采信基线」「无静态契约检查项，豁免」为由降级或排除本节任一缺陷。
{{g38}}
{{g39}}6. 【真相源反查（判据必须落在权威源上）】：对本次改动**新增或改动**的每一个 `if <flag>` / `if (<条件>)` 门控，逐一反查该判据的**权威源**——最底层那一个唯一真相：真实字段、系统调用返回值、事件源、用户输入。逐条回答：① 门控直接读权威源，还是读派生投影（缓存标志、状态字符串、上层聚合值、配置回显值）？② 若读投影，枚举**全部**能合法写该投影的代码路径，判定其中是否存在「投影写方把守卫喂死」——投影被写成与真相相反的值而门控仍放行。凡本次改动内**新写**的字段/变量又被同一改动的门控直接读取（读写自环），先机械枚举该字段/变量的**写入路径集**并把逐条结果写入本节反查表：写入路径唯一、且该唯一写入直接取自权威源（单写单读直通、此后只读）的，按实际影响定级，不得仅凭读写同源即判 Critical；存在**第二条**写入路径（默认值初始化、缓存刷新、状态机迁移、异常回退、写后读、多处手工赋值对齐）的，须按门控是否真的会出错定级——只有当该写入路径**可能使投影偏离权威源并导致门控错误放行**时，才报告缺陷并按实际影响（Critical/Important/Minor）定级；两条写入路径都从同一权威字段直通派生、且时序上互斥或等价写入的合法实现，不得仅凭写入路径条数判 Critical。反查表须逐条写明「该写入能构造的具体输入 → 投影值 → 门控决策」三段，缺任一段即视为未追踪到位。**强度下限**：存在**第二条**写入路径的字段，该路径必须逐条列入反查表，未列入即按 `TRUTH_PASS=partial` 处置；仅当逐条核验确认该写入在全部现实时序下都不会使投影偏离权威源、门控不会误放行时，方可降级或不计缺陷——放宽的是定级档位，不是追踪义务本身。
{{g40}}7. 【读纯度与多真相源】：① 命名语义为读（`get_` / `fetch` / `query` / `list` / `read` / `peek` / `status` / `describe`）的路径若写入共享状态、缓存、单例或模块级变量，一律判 Critical（读接口副作用），并逐条列出被污染的下游消费点及其在旧契约下的解读；② 同一语义（如"是否运行""是否完成""是否已同步"）若在两处及以上独立存储、靠手工赋值对齐而无单一权威源，一律判 Important 并要求收敛到单一权威源；两处各写各的、任一处漏写即产生可观察行为分叉的，判 Critical。
{{g41}}8. 【异常路径回滚与持锁活性】：① 对本次改动涉及的**每个** try / catch（或等价错误分支）块，列出成功路径写过的**全部**副作用（文件、缓存、持久化键、临时状态、消息、锁、游标），逐项核对 except / 早退 / 超时 / 重试分支是否撤销**同一批**副作用；「成功清 X、失败不清 X」直接判 Critical。② 对每个持锁区间，枚举区间内发生的全部外部操作（无超时 join / 进程等待 / 网络 / 文件 IO / 再次取锁 / 消息投递）；其中任一为可能无界阻塞者即判 Critical 活性缺陷，并给出可构造该阻塞的触发输入——happy path 全绿不构成抗辩，「测试未复现挂死」同样不构成抗辩，按本节以嫌疑未排除处理。
{{g42}}9. 【夹具保真度对账（替身不得比生产更配合）】：对每个验证本次新增守卫/校验的用例，逐个替身（mock / stub / fake / 简化实现）产出保真度对账表：替身方法名 → 生产实现的 `路径:行号` → 逐条副作用差异（返回值、写入、抛出、异步时序）。受只读铁律约束无法把替身换成生产副作用复跑时，必须标注 `FIXTURE_RERUN=BLOCKED_READONLY` 并把该用例的保真度按未验证记账，按 Important 处置；严禁以「读着像真的」或「测试全绿」直接放行。

{{g47}}## 审查模式与证据核验（双轨 · 真红 · 容错）
{{g48}}
{{g49}}调度者传入字面量参数：`MODE`、`BASE_REF`、`SCOPE_DIRS`、`PLAN_PATH`、`EVIDENCE_LOG`、`报告路径：`。
{{g50}}
{{g51}}**缺省规则（不得落入未定义分支）**：缺 `MODE` 按 `single` 处理；`MODE=cumulative` 而缺 `BASE_REF` 时判「参数缺失，退回调度者」，不得自行猜测基线；缺 `PLAN_PATH` 时范围逃逸判定记「不可判」，不得默认通过；缺 `EVIDENCE_LOG` 时按第二节判 Critical。
{{g52}}
{{g53}}### 一、双轨审查模式
{{g54}}
{{g55}}1. **MODE=single（默认）**：审查对象 = 工作区未提交变更集。先 `git status --short -uall` 定位全部改动（含未跟踪新文件），再用 `git diff`（未暂存）与 `git diff --cached`（已暂存）取逐行 hunks。
{{g56}}2. **MODE=cumulative（累积全景）**：审查对象 = 自基线引用以来的累积变更。先 `git status --short -uall`，再平铺运行 `git diff BASE_REF` 与 `git diff BASE_REF -- SCOPE_DIRS`（`BASE_REF` 与 `SCOPE_DIRS` 以调度者给出的真实字面量代入）。
{{g57}}4. **范围逃逸判定**：变动文件必须属于 `PLAN_PATH` 声明的 Files 集合；`.kilo/` 内部文件与编译衍生文件（`*.tsbuildinfo`、`.cache/` 等）自动免审免判。
{{g58}}
{{g59}}### 二、证据日志（`EVIDENCE_LOG`）真红核验
{{g60}}
{{g61}}读取 `EVIDENCE_LOG` 并逐条判定，且须**先核对 `PLAN_PATH` 是否显式标注「本文档类任务经判定豁免 Red-Light Protocol」**：
{{g62}}- **文档类任务豁免核验**：若计划已显式声明豁免，确认常驻不变式（checks 套件）Exit 0 且改动为纯文本即可判定通过，严禁因「无代码真红日志」判 Critical；
{{g63}}- **代码修改类真红核验**：确认含断言/比对失败、目标契约缺失型类型错误、业务领域异常或异步时序超时之一；排除 SyntaxError、Cannot find module、脚手架崩溃等无效假红。日志缺失、为空或只含无效假红 → 判 **Critical**。
{{g64}}
{{g65}}### 三、动态复测与静态契约
{{g66}}
{{g67}}- 复跑受影响单测，必须全部 Exit Code 0；单条命令上限 60 秒，超时则采信有效基线日志并在报告中声明「复跑超时，转为采信基线」；
{{g68}}- 运行静态全量契约检查：命令必须取自宿主只读探测结果**且落在执行者受控通道的 ALLOW 键集内**。**若项目不存在该类检查项，或该命令不在 ALLOW 键集内（受控通道 0 弹窗拒绝），记为「无静态契约检查项，豁免（附探测与拒绝回执原文）」并继续流程，严禁伪造 Exit Code 0，也严禁据此判 Critical 或 Deadlock；仅当命令在场、可跑而跑出非 0 时，才计入失败。** 另注：**本豁免不适用于「真相源、读纯度与活性四问」**——静态检查命令缺场不构成四问任一节的免测理由，四问以代码直读与权威源核对取证，不以该命令是否在场为条件。

{{g105}}**勘误（ERRATA）通道**：需推翻本报告已落盘的"拦截/已修/GO"判定时（下游 bot、人类或新会话反例触发），严禁静默改写原句；必须在报告末尾追加 `## ERRATA` 节：原判定行引用 → 修正后判定 → 证伪反例（`路径:行号` + 触发输入）→ 影响面与链台账同步口径。原判定行引用**必须以行内代码或闭合围栏承载，或改写为不满足行锚定的形态**（如行尾缀"（已推翻）"、前缀"原判定："）；严禁在围栏外以独立整行复写旧 `VERDICT:` / `SEMANTIC_PASS=` / `TRUTH_PASS=` 判定行——机读一律取围栏外最后一次出现，ERRATA 位于报告最末，裸复写旧行会让末次值退回被推翻判定，勘误静默失效。**唯一例外**：允许在 `## ERRATA` 节末尾以围栏外独立整行写入**修正后**的机读行，且必须逐字命中机读锚定正则——机读行分两类锚定，失效语义不同。第一类：`VERDICT: GO` / `VERDICT: NO-GO` / `VERDICT: ESCALATE_TO_HUMAN`，由 `VERDICT_LINE_RE` 整行闭合锚定，值域为三值闭集；写入三值之外的任何值不会命中锚定，末次取值仍落在被推翻的旧行上，勘误静默失效。第二类：`TRUTH_PASS=done` 或 `TRUTH_PASS=partial:<缺项>`、`SEMANTIC_PASS=done` 或 `SEMANTIC_PASS=partial:<缺项>`，锚定（`TRUTH_PASS_LINE_RE` / `SEMANTIC_PASS_LINE_RE`）取值域为闭集：`done` 与 `partial:<非空缺项>`（行尾仅容忍空格/制表符硬换行）；写入闭集外的修正值（如纯字母拼错的 `TRUTH_PASS=dnoe`、裸 `TRUTH_PASS=partial`）不命中锚定，末次取值退回被推翻的旧行，且该围栏外行首机读行被值域外机读行闸判红（pass-line-out-of-domain-gate：围栏外行首 `^TRUTH_PASS=` / `^SEMANTIC_PASS=` / `^SHADOW_PASS=` 整行但不命中对应取值正则即红，selftest `assert-truth-pass-out-of-domain-stray-line-detected` 等三族断言钉死）——机器信号在场，但信号归因是「修正行取值非法」而非四问/五问真缺项，写入修正行后仍必须人工核对取值拼写逐字为 `done`（或 `partial:<真实缺项>`）。两类修正行均必须整行锚定（`^…$` 整行闭合），行尾容忍面逐类不同：`TRUTH_PASS=` / `SEMANTIC_PASS=` 修正行行尾仅容忍空格/制表符与可选 `:说明`；`VERDICT:` 修正行行尾仅容忍空格/制表符，不得续写 `:说明`——`VERDICT_LINE_RE` 无可选说明组，续写即不命中锚定。`VERDICT` 修正行写入三值闭集外的值、行尾续写 `:说明`，或任一修正行不命中锚定正则时，末次取值仍落在被推翻的旧行上，勘误静默失效。独立 `<修正值>` 裸值整行不属于本例外：裸值整行不被 PR 侧机读闸消费（值语义闸严格锚 `^VERDICT:` 整行闭合，selftest `assert-truth-pass-verdict-strict-anchor-not-hijacked` 钉死），写了不生效即勘误失效；一旦为容它而放宽锚定即成劫持面。修正行之外的一切散文与行内代码引用仍不构成机读行。
