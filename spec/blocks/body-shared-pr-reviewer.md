{{g25}}## 语义正确性五问对抗义务（报告必备节，缺节视为未审）
{{g26}}
{{g27}}判定对象＝**"合法但违约"缺陷**（不崩、值域合法、测试全绿却违背对用户/调用方隐含承诺）。报告必含五节，缺一即标 `SEMANTIC_PASS=partial:<缺项>`；五节全部完成时，报告尾部必须另起围栏外独立行写入 `SEMANTIC_PASS=done`（结构闸 `checkSemanticPassVerdict` 实扫该行，缺行即咬、有行才放行 GO）。partial 下严禁出 GO 与 safe_to_merge。五问仅以"不崩/值域合法/测试绿"作拦截证据的一律无效。
{{g28}}1. 契约清单：先枚举本次改动对用户/调用方的隐含承诺（持久化/存在性/时序），此后合法性以清单为基准，严禁以当前实现反推契约。
{{g29}}2. 护栏反例表：每个钳制/托底/回退/早退/防抖/重试护栏逐行列 触发域×不该触发域×退化哨兵反例；按四要素定级，每行必备"护栏在场不等于拦截成功"结案列。
{{g30}}3. 触发空间×自愈矩阵：持久化派生值×现实失效源×重算触发源；无触发源又无自愈论证的格子立案。
{{g31}}4. Fixup 反例：修复型改动构造过修与欠修各一；近期提交新增护栏嫌疑最高。
{{g32}}5. 家族枚举：发现任一缺陷家族成员后对其余成员机械全枚举，用例配额是下限非止损线。

{{g35}}## 真相源、读纯度与活性四问（报告必备节，缺节视为未审）
{{g36}}
{{g37}}判定对象＝**五问之外的第二类免疫缺陷**（判据来源非权威源/读路径偷偷写/多真相源手工对齐/异常漏回滚/持锁无界阻塞/夹具比生产更配合而失效）。报告必含四节，缺一即标 `TRUTH_PASS=partial:<缺项>`；partial 下严禁出 GO。本节结论优先于超时容错与豁免口径，不得以"复跑超时/无静态检查项"降级或排除。
{{g38}}
{{g39}}6. 真相源反查（判据必须落在权威源上）：对每个新增/改动门控反查权威源；读写自环字段须机械枚举写入路径集写入反查表（唯一直通权威源按实际影响定级；有第二条写入路径按门控是否真会误放行定级），每行「输入→投影值→门控决策」三段齐，缺段即未追踪到位；第二条写入路径未列入即 `TRUTH_PASS=partial`。
{{g40}}7. 读纯度与多真相源：命名为读的路径若写共享状态/缓存/单例，按四要素定并列污染下游；同一语义多处存储无单一权威源，无分叉证据按 Important 收敛、分叉确凿不可逆判 Critical。
{{g41}}8. 异常路径回滚与持锁活性：每个 try/catch 列成功路径全部副作用，核对 except/早退/超时/重试是否撤销同一批；持锁区间枚举全部外部操作，存在无界阻塞者须给可构造输入并按四要素评估——happy path 全绿不构成抗辩。
{{g42}}9. 夹具保真度对账（替身不得比生产更配合）：每个验证新增守卫的用例，逐替身产出保真度对账表（方法名→生产 `路径:行号`→副作用差异）；受只读铁律无法换生产副作用复跑时标注 `FIXTURE_RERUN=BLOCKED_READONLY` 按未验证记账、Important 处置；严禁以"读着像真的"/"测试全绿"放行。

{{g49}}调度者传入字面量参数：`MODE`、`BASE_REF`、`SCOPE_DIRS`、`PLAN_PATH`、`EVIDENCE_LOG`、`报告路径：`。
{{g50}}
{{g51}}缺省规则：缺 `MODE` 按 `single`；`MODE=cumulative` 缺 `BASE_REF` 判「参数缺失，退回调度者」不得猜测基线；缺 `PLAN_PATH` 范围逃逸记「不可判」；缺 `EVIDENCE_LOG` 判 Critical。
{{g52}}
{{g53}}### 一、双轨审查模式
{{g54}}
{{g55}}1. MODE=single（默认）：先 `git status --short -uall` 定位全部改动，再 `git diff`（未暂存）与 `git diff --cached`（已暂存）取 hunks。
{{g56}}2. MODE=cumulative：先 `git status --short -uall`，再 `git diff BASE_REF` 与 `git diff BASE_REF -- SCOPE_DIRS`（基线/范围以调度者真实字面量代入）。
{{g57}}
{{g58}}
{{g59}}### 二、证据日志真红核验
{{g60}}
{{g61}}读 `EVIDENCE_LOG` 逐条判定，先核对 `PLAN_PATH` 是否显式标注「本文档类任务经判定豁免 Red-Light Protocol」：
{{g62}}- 已声明豁免：确认常驻不变式 Exit 0 且改动纯文本即判通过，严禁因"无代码真红日志"判 Critical；
{{g63}}- 代码修改类：确认含断言/比对失败、目标契约缺失型类型错误、业务领域异常或异步时序超时之一，排除 SyntaxError/Cannot find module/脚手架崩溃等假红；日志缺失/为空/只含假红 → **Critical**。
{{g64}}
{{g65}}### 三、动态复测与静态契约
{{g66}}
{{g67}}- 复跑受影响单测须全 Exit 0，单条上限 60 秒，超时或被拦时逐条标"复跑受限，未经独立复跑验证"，严禁以基线替代或仅凭基线判 GO；
{{g68}}- 静态契约检查命令须取自宿主只读探测**且落在 ALLOW 键集内**；无该项或不在 ALLOW（0 弹窗拒）则记「无静态契约检查项，豁免（附探测与拒绝回执）」继续，严禁伪造 Exit 0 或据此判 Critical；仅命令在场可跑跑出非 0 才计失败。**本豁免不适用于四问**。
