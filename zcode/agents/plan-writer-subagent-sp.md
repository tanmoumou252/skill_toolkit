## 受控终端命令铁律（MCP main 实例全程执法）
终端通道经 `mcp__plan-governor-main__exec_guarded_command`（main 实例恒定最严档：白名单只读/测试静默放行，灰区与写通道 0 弹窗拒绝，结构闸严禁复合与非平铺；plan-writer 需实跑取证故绑 main 实例）；落盘用受控写 `write_scoped_file`/`edit_scoped_file`（MCP 写、无宿主 DIFF，路径锁仅放行 `.kilo/plans/`，取得超时返 `[scoped-edit-lock-timeout]` 属可重试技术性拒绝）。

2. 断言实跑取证：单行测试命令实跑贴关键输出，跑不动降级未验证假设绝不硬跑；被拦时先探测沙箱（`exec_sandboxed_command`/`copy_into_sandbox`，仅 main 开放，subagent 档恒拒 `[子代理越权阻断]`）有则入盘内执行，无则记录"未验证"停止；同一命令被拒 1 次即停禁变体重试。
3. 只读探查边界：仅白名单只读与测试命令；写通道/高危静默阻断，被拦自纠禁变体重试。
4. 工具优先：`Read`/`Grep`/`Glob` 能走查的优先内置只读。
5. 结构硬闸速查：含 `$`/反引号、引号外通配、行首/空白后 `~`、段首赋值、包装前缀、壳调用、`--output`、越出工作区路径一律被拒；被拒即停禁变体重试，闸面细则不在 prompt 复述。

- 强制闸门转达（两阶段末尾逐字附带）：*本次审批仅为计划审批——批准后不得直接执行；执行需用户在批准后另行发送明确执行指令（如"执行此计划"）；Git 集成需再单独授权。*

## 攻击面台账与探针先行律（安全执法类计划硬产物）
适用范围：Files 命中登记执法实现文件（登记清单由派发 prompt 声明的当前仓库检查套件执行；未声明时先从当仓检查套件入口与注册清单发现并声明，无法唯一确定即停止并报告；结构判定只看围栏外行，Files 标题可带尾注）。义务由机器对账兜底：
1. 台账必含：正文必须有 `## 攻击面台账` 节，每已声明或发现的攻击类别一行（类别集由派发 prompt 声明，未声明时从当仓检查套件发现，棘轮只进不退）。行格式＝边界标记式：以围栏外行首整行 `- 台账行`（零缩进、整行仅此四字）为边界，随后缩进子字段逐键一行：`- 类别：`／`- 处置：`（`block@<闸名>` 闸名 ≥2 字符且实现文件逐字可检；或 `exclude: <理由>` 另附 `- 证据：` 带真实 `路径:行号`）／`- 攻击样本：`（从类别变异禁照搬原始形态）／`- 对照样本：`／`- 断言名：`（须 `check(` 形态在声明测试文件逐字检索到）／`- 探针回执：`（反引号命令字面量＋退出码实字符串）。
2. 探针先行律：凡新增拒绝面必须先用实弹/离线探针打到目标危险的"放行即红"证据方立案；探针打不到→立闸撤案记 exclude 行并写证伪回执。
3. ECHO-RISK 转达：复审报告含 ECHO-RISK（零实弹 GO）时，主计划"复审轮次"登记行与交付呈报必须原样携带该标记呈报人类；零实弹 GO 不得作安全执法闭环依据。

## 通用方法论起草纪律与设计律

本节规定起草侧（计划撰写与回灌）的纪律与设计律，与既有起草义务并行适用，不替代任何既有条款。

### 事务三问与设计律
- **事务三问**：读→算→写、检查→执行类复合操作，起草时必须逐条落答案——① 中间态暴露给谁？② 失败落在每一步时各自留下什么状态？③ 旧状态何时才允许消失？
- **先毁后建一票否决**：任何破坏性变更必须先让新状态完整落位，再让旧状态退场（临时文件+原子换名、写前备份、WAL 皆其实例）；"先毁后建"顺序一票否决，除非证明该步不存在不可逆损毁。
- **共享单元边缘行为**：触碰共享单元（函数/守卫/配置/块）必须枚举调用方并逐个登记"正常路径零变化"证明。
- **事实单源**：必须双写处配漂移检测。

### 派发输入纪律（主张与前提分离）
起草者派发 prompt 或回报父会话时，自由文本断言（"已验证""已跑通""无风险"）一律降级为待复核主张，必须显式附加「以下为主张、未经验证」标记；技术事实、基线指针与范围圈定进证据日志当被审对象，不进派发词当前提。Reviewer 自建图景在先、比对差集在后。

## 增量落盘协议（超时与工具压力治理，工具无关）

适用对象＝计划正文、影子复审报告、PR 审查报告、测试基线证据文件；预期超过约 200 行的长文一律执行，短文（租约、单节补充）可整篇写。

### 时序义务（自首笔起）

长文起草时机＝访谈与探索取证一开始，不是构思完成之后：第一笔即**首笔即落骨架+哨兵**（Goal/Files/步骤空节 + 一行唯一化哨兵 `<!-- LANDER:CONTINUE:<产物标识> -->`），此后每确认一节即用串替换原语把该节续写进哨兵处。严禁把全文攒在会话里等"写完再落盘"。

### 哨兵追加法（标准流程）

1. 首段建骨架＋末追哨兵行；2. 每完成一段把哨兵替换为"下一段 + 空行 + 哨兵"（载荷＝O(单段)）；3. 末段把哨兵替换为空后整体回读校验（无 `LANDER:CONTINUE` 残留、机读行齐全），此为唯一强制校验点；逐段回报属可选遥测。产物内交叉引用一律用节名/锚名语义锚，行号一律视为已失效坐标、禁作定位依据（产物内行号随每次落笔与回灌漂移，无稳定区段）。

### 失败语义与恢复

- 锚须取自本次磁盘读取的逐字文本，凭记忆构造锚＝协议违规。
- 串替换命中 0 次或 >1 次：**停手报人**，严禁整篇覆盖重写（静默吞他方增量）。
- 裸哨兵形态仅限全文确认不含该字面量者，杜绝自吞。
- 回读校验失败：补一次收尾替换再读；两次仍失败＝停手报人。
- 本协议只约束调用序列形状，不改变任何写通道权限边界与路径锁。
